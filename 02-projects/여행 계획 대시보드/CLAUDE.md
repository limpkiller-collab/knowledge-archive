[작업규칙]

ㅇ 실행 전 필수 사항
 - 00-context 폴더의 모든 파일을 먼저 읽을 것(작업과 관련된 파일 우선, 전체는 처음 세션 시작 시 1회)
 - 작업이 불명확하면 추측하지 말고 질문할 것
 - 파일을 수정하기 전에 반드시 계획을 먼저 보여줄 것
 - 승인 없이 파일을 삭제하지 말 것

ㅇ 폴더 구조 규칙
 - 00-context/     : 컨텍스트 및 참고용 .md 파일 저장
 - 01-input/       : 프로젝트 전역에 해당하는 지식(도메인 용어 및 법률)
 - 02-projects/    : 모든 프로젝트 산출물 저장
 - 03-skills/      : .skill 파일 저장 (스킬 실행 시 이 폴더의 .skill 파일을 우선 참조)

 [02-projects/ 하위 구조]
 - 일반 프로젝트 : 02-projects/[YYYY-MM]프로젝트명/
 - 회의록 프로젝트 : 02-projects/회의록/[카테고리]/YYYY-MM-DD/
   - 카테고리 종류: CPL/, Loan Excellence/, 기타(외부)/, 기타(내부)/
   - 같은 날짜에 회의가 2건 이상인 경우 YYYY-MM-DD_회의명/ 형식으로 구분
   - 예시: 02-projects/회의록/CPL/2026-03-16/
   - 예시(동일날짜): 02-projects/회의록/CPL/2026-03-23_CPL_Weekly/

 - 각 프로젝트 폴더 하위에 input/, output/ 폴더를 함께 생성할 것
 - 첨부파일이 업로드되면 해당 프로젝트 폴더의 input/에 즉시 복사 저장할 것 (모든 프로젝트 공통 적용)
   - 사용자가 별도로 요청하지 않아도 업로드 시점에 자동으로 저장할 것
 - .md 파일(컨텍스트·참고용)은 02-projects가 아닌 00-context/에 저장할 것
 - .skill 파일은 02-projects가 아닌 03-skills/에 저장할 것

ㅇ 결과물 저장 규칙
 - 모든 산출물은 02-projects/[YYYY-MM]프로젝트명/output/ 에 저장
 - 만약 동일 업무에 대한 프로젝트 폴더가 생성되어있는 경우 폴더를 새로 생성하지 않고 해당 폴더를 활용 
 - 파일명 형식 : 주제_세부업무명_버전명_생성일자.확장자
   - 주제     : 프로젝트명
   - 세부업무명 : 프로젝트에서 수행한 세부내용(간략히)
   - 버전명   : v1, v1.1, v1.2, v2, v3 방식(오류 수정 등의 작은 사항은 0.1씩 올리고, 큰 변경작업은 1단위)
   - 생성일자  : YYYY.MM.DD 형식
   - 예시     : 공간의가치_분류검증대시보드_v1_2026.03.15.html
   - 기존 버전은 삭제하지 않고 새로운 버전으로 저장

ㅇ 프로세스
 - 먼저 질문 → 계획 → 승인 → 실행 순서를 반드시 지킬 것
 - 큰 작업은 단계별로 나누어 중간 점검할 것

ㅇ Playwright 사용 규칙
다음 중 하나라도 해당하면 사용
 - 로그인, 클릭, 폼 입력 등 브라우저 조작이 필요할 때
 - 특정 웹사이트에서 직접 작업을 수행해야 할 때
 - 스크린샷 캡처가 필요할 때
 - Firecrawl로 안 되는 인증/세션 필요 페이지 접근 시 
 ❌ 단순 웹 내용 읽기는 Firecrawl이 더 적합

ㅇ Context7 사용 규칙
 - 코드 생성, 라이브러리/API 사용법, 설정 방법 관련 질문 시 항상 Context7을 자동으로 사용할 것
 - 다음 상황에서는 반드시 Context7을 먼저 호출할 것:
   - 외부 라이브러리 코드 예제 제공 시 (React, Next.js, FastAPI, Playwright 등)
   - 라이브러리/프레임워크 설정 및 설치 방법 안내 시
   - API 사용법 또는 함수 시그니처 안내 시
   - 버전별 문서가 필요한 경우
 - 사용자가 명시적으로 "context7 사용하지 마" 라고 하지 않는 한 자동 적용

ㅇ Sequential Thinking 사용 규칙
 - 복잡한 문제 분석, 다단계 계획 수립, 설계 작업 시 항상 Sequential Thinking을 자동으로 사용할 것
 - 다음 상황에서는 반드시 Sequential Thinking을 먼저 호출할 것:
   - 여러 단계가 필요한 복잡한 작업 계획 수립 시
   - 버그 원인 분석 또는 오류 디버깅 시
   - 아키텍처 설계 또는 시스템 구조 결정 시
   - 트레이드오프 분석이 필요한 의사결정 시
   - 전체 범위가 처음에 명확하지 않은 작업 시
 - 사용자가 명시적으로 "sequential thinking 사용하지 마" 라고 하지 않는 한 자동 적용

ㅇ Firecrawl MCP 활용 지침
 웹 정보가 필요할 때는 Firecrawl MCP를 적극적으로 활용한다.
 # 도구 선택 기준 
  - URL을 알 때. → firecrawl_scrape
  - 주제만 알 때 → firecrawl_search(최신 정보: tbs 파라미터로 qdr:d/w/m 활용)
  - 여러 URL 동시 처리 → firecrawl_batch_scrape (개별 scrape 반복 금지)
  - 사이트 전체 구조 파악 → firecrawl_map → batch_scrape 순서
  - 사이트 전체 수집 → firecrawl_crawl (limit 옵션 필수)
  - 심층 자율 리서치 → firecrawl_deep_research
  - URL 없이 자율 탐색 → firecrawl_agent 
 # 포맷 원칙
  - 특정 필드만 필요할 때 → json 포맷 + schema 지정 (크레딧 절약)
  - 전체 본문이 필요할 때 → markdown 포맷 
  - Enhanced Mode는 401/403/500 오류 시에만 사용 
 # 업무 연계
  - 리서치 결과 → Notion MCP로 자동 저장
  - 뉴스/동향 → Slack MCP로 공유
  - 복잡한 분석 → Sequential Thinking MCP와 병행
  - 라이브러리 문서 → Context7 MCP와 병행
