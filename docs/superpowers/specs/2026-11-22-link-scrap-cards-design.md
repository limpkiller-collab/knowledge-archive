# 링크 스크랩 카드 — 설계서

- 작성일: 2026-11-22
- 상태: 설계 승인됨, 구현 전
- 대상 리포: `knowledge-archive`

## 1. 목적

아이폰에서 보던 링크(기사, 인스타그램 게시물, 릴스, 유튜브 영상)를 공유 시트로 한 번에 보내면, 내용을 추출해 Claude API로 핵심을 정리하고 카드로 보관한다. 카드는 노션 DB와 이 리포의 HTML 아카이브 양쪽에 자동 저장한다.

## 2. 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 입력 경로 | 아이폰 공유 시트 → 단축어 |
| 보관 위치 | 노션 DB + HTML 아카이브, 둘 다 자동 |
| 운영 방식 | 지식카드와 스크랩을 하나의 목록·하나의 카테고리 체계로 통합 |
| 대시보드 | 에디토리얼 매거진 디자인 + 왼쪽 메뉴로 개편 |
| 인스타그램 범위 | 캡션, 슬라이드 이미지 속 글자, 릴스 음성까지 |
| 실행 환경 | 이 리포의 GitHub Actions (별도 서버 없음) |
| 사용자 | 본인 1명 |

## 3. 전체 흐름

1. 단축어가 공유받은 URL, 카테고리, 선택 메모를 GitHub `repository_dispatch` API로 보낸다. 이벤트 유형은 `scrap-link`, 페이로드는 `{ "url": "...", "note": "...", "category": "..." }`이다(4.7).
2. 워크플로 `.github/workflows/scrap-link.yml`이 실행된다. `concurrency` 그룹을 하나로 묶어 한 번에 한 건씩 순서대로 처리한다.
3. URL을 정규화하고(추적 파라미터 `utm_*`, `igsh` 등 제거) 중복 여부를 확인한다.
4. 추출기가 링크 종류에 맞게 내용을 뽑는다.
5. 요약기가 Claude API로 카드 데이터를 만든다.
6. 노션 저장기가 노션 페이지를 만든다.
7. HTML 저장기가 카드 파일과 `scraps.json`을 갱신하고 커밋·push한다.
8. 알림기가 결과를 아이폰 푸시로 보낸다.

단축어는 요청만 보내고 끝나며, 결과는 1~3분 뒤 푸시 알림으로 받는다.

## 4. 구성 요소

코드는 Python으로 작성하고 `scrap/` 아래에 둔다. 각 모듈은 한 가지 일만 하고, 아래 입출력으로만 서로 연결된다.

### 4.1 단축어

- 입력: 공유 시트의 URL. 실행 시 카테고리(4.7)와 메모 한 줄을 물어본다(메모는 비워둘 수 있음).
- 동작: `POST /repos/limpkiller-collab/knowledge-archive/dispatches` 호출.
- 인증: 이 리포에만 권한을 준 세분화 토큰(fine-grained PAT). 필요한 최소 권한은 구현 첫 단계에서 GitHub 문서로 확인해 적용한다.

### 4.2 추출기 `scrap/extract.py`

- 입력: 정규화된 URL
- 출력: `{ source_type, title, author, published_at, text, images[], transcript, thumbnail_url, warnings[] }`
- `source_type`은 `article`, `instagram_post`, `instagram_reel`, `youtube` 중 하나다.
- `thumbnail_url`은 기사의 대표 이미지(`og:image`), 인스타 게시물의 첫 이미지, 릴스와 유튜브의 영상 썸네일이다. 없으면 비워 둔다.

| 종류 | 판별 | 추출 방법 |
|---|---|---|
| 기사 | 그 외 모든 URL | 페이지를 받아 본문 추출 라이브러리로 본문·제목·작성자·날짜를 뽑는다 |
| 인스타 게시물 | `instagram.com/p/` | 스크래핑 서비스로 캡션과 슬라이드 이미지 URL을 받는다. 이미지는 최대 10장까지 요약기로 넘긴다 |
| 릴스 | `instagram.com/reel/`, `/reels/` | 스크래핑 서비스로 캡션과 영상 URL을 받고, 음성을 뽑아 음성인식 API로 받아쓴다 |
| 유튜브 | `youtube.com/watch`, `youtu.be/`, `youtube.com/shorts/` | Gemini API에 영상 주소를 넘겨 내용을 글로 받는다 |

Claude API는 오디오를 직접 받아쓰지 못하므로 릴스에는 별도 음성인식 API가 필요하다.

유튜브는 Gemini API가 공개 영상 주소를 직접 받아 영상과 음성을 읽고 내용을 글로 풀어 준다. 그 글을 다른 링크와 똑같이 Claude 요약기로 넘긴다. 자막 유무와 상관없이 처리되며, 비공개 영상이나 길이 한도를 넘는 영상은 추출 실패로 처리한다.

### 4.3 요약기 `scrap/summarize.py`

- 입력: 추출 결과 + 사용자 메모 + 통합 카테고리 목록(4.7) + 단축어에서 지정한 카테고리
- 출력(구조화 JSON):

```json
{
  "title": "카드 제목",
  "summary": "한 줄 요약",
  "key_points": ["핵심 포인트 3~7개"],
  "category": "통합 카테고리 중 하나",
  "tags": ["태그 3~5개"],
  "cover_word": "생성 커버에 쓸 대표 키워드 한두 단어",
  "slug": "영문-소문자-하이픈"
}
```

- 인스타 슬라이드 이미지는 Claude 비전 입력으로 함께 넘겨 이미지 속 글자를 읽게 한다.
- 카테고리는 4.7의 규칙을 따른다. 단축어에서 카테고리를 지정했으면 그대로 쓰고, "자동 분류"면 목록 안에서 고르며 맞는 것이 없으면 `etc`로 둔다.
- 모델은 환경 변수 `CLAUDE_MODEL`로 바꿀 수 있게 하고 기본값은 `claude-opus-5-5`로 한다.
- 출력이 형식에 맞지 않으면 1회 재시도하고, 또 실패하면 실패로 처리한다.

### 4.4 노션 저장기 `scrap/notion_store.py`

개인 워크스페이스에 DB "링크 스크랩"을 새로 만든다. 기본 뷰는 갤러리다.

| 속성 | 유형 | 내용 |
|---|---|---|
| 제목 | 제목 | 카드 제목 |
| URL | URL | 정규화된 원본 링크 |
| 출처 유형 | 선택 | 기사 / 인스타 게시물 / 릴스 / 유튜브 |
| 카테고리 | 선택 | 요약기가 고른 카테고리 |
| 태그 | 다중 선택 | 태그 |
| 한 줄 요약 | 텍스트 | 한 줄 요약 |
| 저장일 | 날짜 | 처리한 날짜 |
| 상태 | 선택 | 완료 / 부분 완료 / 실패 |
| 메모 | 텍스트 | 단축어에서 적은 메모 |
| HTML 카드 | URL | 아카이브 카드 주소 |

링크 썸네일이 있으면 노션 페이지 커버로도 쓴다(4.9). 페이지 본문에는 핵심 포인트 목록, 추출 원문(토글 안), 경고 사항을 넣는다. 같은 URL의 행이 이미 있으면 새로 만들지 않고 그 행을 갱신한다.

### 4.5 HTML 저장기 `scrap/html_store.py`

- 공통 템플릿 `scrap/card_template.html`로 `cards/scrap-YYYYMMDD-<slug>.html`을 만든다. 템플릿은 개편한 대시보드(4.8)의 에디토리얼 디자인을 따르고 다크 모드를 지원하며 구성은 단순하다(제목, 출처, 한 줄 요약, 핵심 포인트, 원문 링크).
- 카드 목록은 `index.html`에 직접 넣지 않고 리포 루트의 `scraps.json`에 추가한다. 항목은 `id`, `title`, `file`, `date`, `source`, `sourceUrl`, `sourceType`, `tags`, `summary`, `category`, `cover`를 가진다.
- `index.html`은 로드 시 `scraps.json`을 읽어 기존 목록과 합쳐 하나의 목록으로 보여준다(4.8). `scraps.json`을 읽지 못해도 기존 지식카드는 정상 표시되어야 한다.
- 변경분을 `main`에 커밋·push한다. push가 거절되면 rebase 후 1회 재시도한다.

`index.html`의 인라인 목록은 사람이 Claude 세션에서 직접 편집하는 코드라, 자동 삽입은 깨지거나 충돌하기 쉽다. 별도 파일로 분리하는 이유다.

### 4.6 알림기 `scrap/notify.py`

- 무료 푸시 서비스(ntfy)의 비공개 토픽으로 보낸다.
- 성공: 카드 제목, 노션 페이지 링크.
- 부분 완료·실패·중복: 무엇이 안 됐는지 한 줄.

### 4.7 카테고리

지식카드와 스크랩은 하나의 카테고리 체계를 함께 쓴다.

| 통합 카테고리 | 기존 카테고리에서 옮겨 오는 것 | 현재 카드 수 |
|---|---|---|
| 경제·투자 | 투자·주식(30), 경제·거시(17), 투자·금융(12) | 59 |
| 기술·산업 | 기술·산업 | 26 |
| 부동산 | 부동산 | 6 |
| 시사·컬처 | 시사·컬처 | 15 |
| 패션 | 신규 | 0 |
| 테크 | 신규 | 0 |
| etc | 신규 | 0 |

- 목록은 리포 루트의 `categories.json`에 둔다. 대시보드, 요약기, 단축어가 모두 이 파일을 읽는다.
- "기술·산업"과 "테크"는 다음 기준으로 나눈다. 기술·산업은 산업 구조, 기업 전략, 시장 분석이다. 테크는 AI와 도구의 활용법, 제품, 개발 실무다. 이 기준을 요약기 지시문에 넣는다.
- 추가 방법은 두 가지다. 단축어에서 "새 카테고리 입력"을 골라 이름을 적으면 워크플로가 목록에 추가한다. 또는 `categories.json`을 직접 고친다.
- 삭제와 이름 변경은 파일을 직접 고친다. 이미 저장된 카드의 카테고리는 바꾸지 않는다.

단축어의 카테고리 선택 흐름:

1. 단축어가 GitHub API로 `categories.json`을 읽는다.
2. 메뉴를 보여준다: "자동 분류", 목록의 각 카테고리, "새 카테고리 입력".
3. 선택 결과를 페이로드의 `category`에 담아 보낸다. "자동 분류"면 빈 값으로 보낸다.

페이로드는 `{ "url": "...", "note": "...", "category": "..." }`가 된다. 목록을 읽지 못하면 단축어는 "자동 분류"로 보낸다.

### 4.8 대시보드 개편과 통합 운영

지식카드와 스크랩을 나누지 않고 하나의 목록으로 운영한다. 대시보드(`index.html`)는 아래 내용으로 개편한다.

- 디자인: 에디토리얼 매거진 방향(흰 바탕, 굵은 제목, 검은 괘선, 강조색 하나)에 왼쪽 메뉴를 더한다. 기준 시안은 캔버스의 "확정안" 아트보드다.
- 왼쪽 메뉴: 전체, 통합 카테고리별 개수, 카테고리 추가, 형식 필터(직접 정리 / 기사 / 인스타그램 / 릴스).
- 본문: 최신 카드 한 장을 머리기사로 크게, 옆에 최근 추가 목록, 아래에 전체 카드 목록.
- 직접 정리한 카드와 자동 스크랩 카드는 같은 목록에 섞여 나오며, 카드의 형식 표시로만 구분한다.
- 전체 카드 목록은 리스트 뷰와 카드 뷰를 전환할 수 있다. 리스트 뷰는 글자 중심 목록이고, 카드 뷰는 카드마다 커버 이미지(4.9)를 얹은 격자다. 마지막으로 고른 뷰를 브라우저에 기억한다.
- 형식 필터에 유튜브를 더한다.
- 아이폰 홈 화면에 추가했을 때 쓰는 아이콘을 둔다. 검은 바탕에 카드 네 장(왼쪽 위 한 장만 붉은색)을 그린 모양이다.
- 기존 기능은 유지한다: 검색, 읽음 표시와 읽음 필터, 태그 필터, 시리즈, 랜덤 보기, 다크 모드.
- 기존 카드 106장의 `category` 값을 4.7의 표대로 바꾼다. 카드 본문 HTML은 고치지 않는다.
- 저장 방식은 그대로 둔다. 직접 정리한 카드는 `index.html`의 목록에, 자동 스크랩은 `scraps.json`에 두고 화면에서 합친다.

리포 밖에서 함께 바꿔야 하는 것: 지식카드를 등록하는 Claude 스킬(knowledge-archive)이 옛 카테고리 이름을 쓰고 있으면 새 이름으로 고쳐야 한다. 이 리포에는 없으므로 구현 계획에 별도 항목으로 넣는다.

### 4.9 커버 이미지

모든 카드는 커버 이미지를 하나 가진다. 카드 뷰와 노션 갤러리에서 쓴다.

| 경우 | 커버 |
|---|---|
| 링크에 썸네일이 있음 (기사 대표 이미지, 인스타 첫 이미지, 릴스·유튜브 썸네일) | 그 이미지를 내려받아 `covers/<카드 id>.jpg`로 저장하고 가로 1200px 이하로 줄인다 |
| 링크에 썸네일이 없음 | 생성 커버 |
| 기존에 직접 정리한 카드 106장 | 생성 커버 |

- 리포와 사이트가 공개이므로 저장한 썸네일도 공개된다. 사용자가 이를 확인하고 저장하기로 정했다(2026-11-22).
- 썸네일을 리포에 저장하는 이유: 인스타그램 이미지 주소는 시간이 지나면 만료되므로 원본 주소를 그대로 쓰면 나중에 깨진다.
- 생성 커버는 AI 이미지 생성이 아니라 대시보드가 화면에서 그리는 글자형 커버다. 카테고리별 바탕색 위에 카드의 대표 키워드를 크게 얹는다. 파일을 만들지 않으므로 기존 카드에도 바로 적용된다.
- 대표 키워드는 자동 스크랩의 경우 요약기가 `cover_word`(한두 단어)로 함께 만들고, 기존 카드는 첫 번째 태그를 쓴다.
- `scraps.json`의 `cover`에는 저장한 이미지 경로를 넣고, 썸네일이 없으면 비워 둔다.
- 노션 페이지 커버는 저장한 이미지의 사이트 주소를 쓴다. 생성 커버인 카드는 노션 커버를 비워 둔다.
- 썸네일 내려받기에 실패하면 생성 커버로 대신하고 실패로 치지 않는다.

## 5. 중복·실패 처리

| 상황 | 처리 |
|---|---|
| 이미 `scraps.json`에 있는 URL | 처리를 건너뛰고 "이미 저장됨" 알림 |
| 추출 실패 (비공개 게시물, 차단 등) | 노션에 링크만 "실패" 상태로 저장하고 알림. HTML 카드는 만들지 않음 |
| 릴스 음성 인식 실패 | 캡션만으로 요약, 상태는 "부분 완료", 카드에 그 사실 표시 |
| 노션과 HTML 중 한쪽만 성공 | 성공한 쪽은 유지, 상태 "부분 완료", 알림에 실패한 쪽 명시 |
| 재시도 | 같은 링크를 다시 보낸다. 실패·부분 완료 건은 중복으로 보지 않고 기존 노션 행을 갱신한다 |

## 6. 외부 서비스와 비밀 값

| 용도 | 기본 선택 | GitHub Secret |
|---|---|---|
| 요약·이미지 읽기 | Claude API | `ANTHROPIC_API_KEY` |
| 노션 저장 | 노션 내부 통합 | `NOTION_TOKEN`, `NOTION_DATABASE_ID` |
| 인스타 추출 | Apify | `APIFY_TOKEN` |
| 릴스 받아쓰기 | OpenAI Whisper API | `OPENAI_API_KEY` |
| 유튜브 영상 읽기 | Gemini API | `GEMINI_API_KEY` |
| 알림 | ntfy | `NTFY_TOPIC` |

스크래핑과 음성인식 서비스는 구현 첫 단계에서 현재 요금과 실제 동작을 확인하고, 문제가 있으면 같은 역할의 다른 서비스로 바꾼다. 추출기 안에서만 바뀌므로 다른 모듈에는 영향이 없다.

인스타그램 추출은 공개 게시물만 가능하고, 인스타그램 쪽 변경으로 예고 없이 실패할 수 있다. 이 경우 5장의 실패 처리로 넘어간다.

## 7. 1차 범위에서 제외

- 카드 수정·삭제 화면 (노션과 리포에서 직접 처리)
- X 등 그 밖의 플랫폼 전용 처리 (일반 기사 방식으로만 시도)
- AI 이미지 생성으로 만드는 커버 (4.9의 생성 커버는 글자와 색으로 그린다)
- 기존 지식카드와의 관련 카드 자동 연결
- 전용 웹앱·PWA 열람 화면

## 8. 검증

- 자동 테스트: 추출기(URL 판별, 정규화), 요약기(출력 형식 검증), HTML 저장기(템플릿 렌더링, `scraps.json` 갱신)를 저장된 샘플 입력으로 테스트한다. 외부 API는 호출하지 않는다.
- 실제 확인: 기사, 인스타 카드뉴스, 릴스, 유튜브 링크를 각 1건씩 단축어로 보내 노션 카드, HTML 카드, `index.html` 표시, 푸시 알림을 확인한다.
- 실패 확인: 비공개 인스타 링크와 이미 저장한 링크를 보내 5장의 처리대로 동작하는지 확인한다.

## 9. 사용자가 직접 해야 하는 일

- 각 서비스 가입과 API 키 발급, GitHub Secrets 등록
- 노션 통합을 만들고 "링크 스크랩" DB에 연결
- GitHub 세분화 토큰 발급 후 단축어에 입력
- 아이폰에 ntfy 앱 설치 후 토픽 구독

## 10. 구현하면서 달라진 점 (2026-11-22)

본문과 아래 내용이 다르면 아래가 우선한다.

- **공개 범위:** 리포와 사이트가 공개이므로 HTML 카드에는 제목, 한 줄 요약, 핵심 포인트, 원문 링크, 커버만 넣는다. 메모와 추출 원문은 노션에만 저장한다.
- **요약기:** 기본 모델(`claude-opus-5-5`)은 도구 강제 호출을 받지 않아, 구조화 출력(`output_config.format`)으로 JSON을 받는다. 모델이 요청을 거절하면 API가 대체 모델로 한 번 더 실행하도록 서버 측 대체 실행을 켰다.
- **노션:** 현재 노션 API는 행 조회와 생성을 DB 안의 데이터 소스 단위로 한다. 저장기는 `NOTION_DATABASE_ID`로 DB를 읽어 첫 번째 데이터 소스를 쓴다.
- **단축어:** 카테고리 목록은 토큰 없이 공개 주소(`https://limpkiller-collab.github.io/knowledge-archive/categories.json`)에서 읽는다.
- **변수:** `CLAUDE_MODEL`, `GEMINI_MODEL`(기본 `gemini-3.8-flash`), `SCRAP_STORE_COVERS`를 리포 변수로 둔다. 모두 선택 사항이다.
- **대시보드:** `index.html`은 카드 데이터와 랜덤 보기 코드를 유지하고 나머지를 다시 작성했다. 기본 테마는 라이트이고, 모바일 하단 메뉴와 카드별 난이도 표시는 없앴다.
- **테스트 위치:** 파이프라인 테스트는 `tests/pipeline/`, 대시보드 로직 테스트는 `tests/archive-core.test.js`에 있다.
- **설정 방법:** `docs/shortcut-setup.md`에 정리했다.
- **아직 실제 호출로 확인하지 못한 것:** Apify 인스타그램 응답의 필드 이름, OpenAI 받아쓰기 호출, Gemini 유튜브 호출, 노션 저장. 키를 등록한 뒤 실제 링크로 확인해야 한다.
